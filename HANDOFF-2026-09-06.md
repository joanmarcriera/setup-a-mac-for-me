## 1. What changed — 2 commits, both in `scripts/update-mac.sh`

**`ca9be96` — only advise macOS-first for real macOS system updates.**
`print_macos_order_advice()` was gated on `macos_update_count()`, which counts *every*
`* Label:` entry in `softwareupdate -l` output — XProtect config data, Safari, Command Line Tools
included. A silent XProtect-only update therefore printed the entire "install macOS first, reboot,
re-run update-mac" block, and disagreed with the python upgrade plan, which matches on `Title:`
lines. Added `macos_system_update_lines()` / `macos_system_update_count()`, matching only entries
whose Title starts with `macOS`, and pointed both the advice and its restart note at those.
`macos_update_count()` is untouched and still backs the all-updates "macOS N" pending summary.

**`20b283d` — state what the run actually does after the advice.**
The run order is deliberately unchanged (Homebrew first, macOS last — `395738b`'s own message says
"Advisory only; the run order is unchanged"), so the note contradicted the very run printing it.
Interactively a user could infer that and Ctrl-C; **under `--yes` there is no prompt at all**, so
the script printed "don't brew before the macOS update" and then non-interactively did exactly
that, causing the CLT/system-library mismatch it warns about. Rather than reorder the run — which
would be a much larger behavioural change than this review's remit — the note now ends by saying
what will happen: a Ctrl-C hint interactively, or a plain "`--yes` is set, this run will NOT stop"
under `-y`. README updated to match.
